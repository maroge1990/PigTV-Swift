**Last updated:** 24 September 2026 · app **1.0 (22)** · server build 0104 (roadmap contracts C-A…C-G in `../PigTV/docs/ROADMAP-CONTRACTS.md`)

## 1. Working rules

- **Push-to-main (Mark, 23 Sept).** Work on `main` in this folder. Claude may `git pull --rebase` and **push to `origin/main`**
  without asking each time. Before every push: the tvOS build and tests pass, plus an iOS build when shared code changed:
  ```bash
  xcodebuild test -project PigTV.xcodeproj -scheme PigTV -destination 'platform=tvOS Simulator,name=Apple TV'
  xcodebuild build -project PigTV.xcodeproj -scheme PigTV -destination 'generic/platform=iOS Simulator'
  ```
  Never force-push. `.gitignore` keeps Xcode and Finder user state out of commits.
- **CI (A0.3).** `.github/workflows/ci.yml` runs on every push to `main` and on pull requests: it selects the runner's
  newest Xcode (failing with a clear message if it is older than the client's minimum), builds for the iOS Simulator, and
  runs the tvOS tests on an Apple TV simulator it finds or creates. It cannot be exercised locally; treat a red run on
  GitHub as equivalent to a local test failure.
- **Bump the build number** (`CURRENT_PROJECT_VERSION`, both app targets in `project.pbxproj`) once per session that changes
  app code, so Settings → Version identifies the installed copy.
- **Organisation:** the lead Claude session delegates implementation to sub-agents and reviews every diff before it's pushed.
  Device-dependent items end with numbered test steps for Mark and become *Verified* only on his report.
- Other internet use still needs Mark's approval: browsing, SDK or dependency downloads, and **contacting the deployed server**.
  Driving the simulator UI (attach, screenshots, input) only when Mark asks in that message; routine checks are `xcodebuild` runs.
- Never send `force: true` automatically: viewer or recording takeover needs an explicit choice. Browsing and focus must never
  acquire a provider stream. Preserve same-origin auth, media URL allow-listing, capability negotiation and release-before-switch.
- Server changes are made in the server repo under its blueprint §2; client-visible server changes appear in
  `../PigTV/docs/SWIFT-CLIENT-HANDOFF.md` §5, so read it at each session start.

## 4. Architecture

- **Screens:** `ContentView` → launch/onboarding/unreachable → `LibraryView` tab container (Guide, Recordings, Settings; `ChannelDetails`/`FavouriteControl` in `LibraryView.swift`). Player is presented full screen via `PlayerHost` → `PlayerScreen` → `CustomPlayerView` (tvOS) or `NativePlayer` (iOS).
- **UIKit guide grid (A2.1, build 20, Labs → "New guide", tvOS only, default off):** when `Labs.newGuide` is on, `GuideView` swaps its time header + `LazyVStack` grid for `GuideGridView` (`UIViewControllerRepresentable` → `GuideGridViewController`), keeping its header, filters, summary area and all sheets/covers; the Now button sits in the header next to Earlier/Later (build 22). One `UICollectionView` with a custom `GuideGridLayout`: section = channel row, item 0 = the channel tile (pinned left via the content offset), items 1…n = programmes at `x = (start − model.window) × pointsPerSecond` over the whole loaded 24 h (2 h = the timeline width), or one day-wide "no programme information" placeholder; a now-line decoration; cells clipped at the channel column with the clipped amount passed to the cell (`GuideGridAttributes.leadingClip`) so titles stay visible. The time header is a separate strip view above the rows that follows `contentOffset.x` (so rows never scroll under it). Horizontal position is owned by the grid: `GuideGridCollectionView` locks `bounds.origin.x`, so the focus engine's own scroll-into-view cannot move it sideways; the grid moves by whole half-hour columns with its own 0.2 s ease-in-out display-link animation (none with Reduce Motion). Focus is the collection view's own: `canFocusItemAt` makes finished programmes unfocusable and, in rows other than the focused one, only the Up/Down target (the programme under the time anchor) focusable; `shouldUpdateFocus` plans the column move for Left/Right and redirects Left-onto-the-tile ahead of the live baseline (step back / return to live) via `indexPathForPreferredFocusedView`. Pure maths (positions, clipping, sticky tile, column reveal, vertical target, left step) is in `GuideGridMath.swift`; the row filter is `GuideRowFilter` (shared with the SwiftUI grid). Rows are applied with a plain data source (append → `insertSections`, anything else → `reloadData` + focus restored by identity), not diffable snapshots, because the real guide has ~18 000 channels × ~30 programmes. Files: `GuideGridMath.swift`, `GuideGridLayout.swift`, `GuideGridCells.swift`, `GuideGridView.swift`; tests `GuideGridMathTests`, `GuideGridNavigationUITests` (launch arg `-pigtv.labs.newGuide YES`).
  **Build 21 follow-ups:** (a) when the player or a details cover closes, GuideView bumps `focusRestoreToken` and the grid refocuses its last programme or tile (what is on now in that row if the programme finished meanwhile); (b) Now, Earlier, Later and Jump to move focus with the grid, to the programme under the new anchor in the last focused row (else the first visible row). In both, the grid makes the target its preferred focus (`claimFocus`) and GuideView moves SwiftUI focus into the representable (`.focused($gridHasFocus)`, `claimGridFocus`, retried at 0/0.4/0.8 s while a cover dismisses) — **`UIFocusSystem.requestFocusUpdate` is refused while a SwiftUI control holds focus**, so this must go through SwiftUI. (c) The long-press menu (`contextMenuConfigurationForItemsAt`) already offered the old grid's items; now covered by a UI test (menu items are exposed as `otherElements`). (d) Programme cells rebuild their SwiftUI content only when `GuideGridMath.clipAppearance` (clipped or not, the title's whole-point shift) changes, not on every frame the clipped amount changes; off-screen/unclipped cells get no `apply` during a slide (their attributes are unchanged). Rasterising was not needed. UI tests: Now after moving right; long-press menu and focus back after details. (Superseded in build 22:) on the remote, Up from the grid goes to the header's right-hand buttons (Details, Jump to…), so Now is only reached via the category chips (All → Down).
  **Build 22:** Now moved into the header's button row (before Earlier/Later, new guide only). Up from the grid's top row lands on it: the grid's `shouldUpdateFocus` refuses the engine's move out of the top (no next index path, heading up) and calls `GuideGridActions.leaveUp`, which sets GuideView's `headerNowFocused`. Only Now and Jump to… pull focus into the grid (`GuideGridRequest.focus`); Earlier/Later leave focus on their button so repeated presses work, and claim no grid target. UI tests: `testNowAfterMovingRight` (Up → Now → Select), `testLaterAndEarlierKeepFocusOnTheHeader`.
- **Guide focus model:** `GuideFocus(channel, start)`; `start == nil` is the channel tile, `-1` the no-EPG placeholder. tvOS focus engine moves between drawn cells; `navigate()` intervenes only when the target is off-screen. `viewport` (half-hour aligned) drives rendering; `model.window` drives 24-hour data loads.
- **Player layering:** conflict/error/reconnecting states replace the player. **tvOS:** `CustomPlayerView` (`CustomPlayer.swift`) is the only player — `PlayerLayerView` video + one overlay switching between hidden / info / scrub / channels / tracks chrome, driven by in-view remote handlers, no AVKit. **iOS/iPadOS:** `NativePlayer` (plain AVKit) + top controls, with `QuickGuidePanel` as the channel sheet. A1.2: on tvOS, the "Preparing…"/reconnecting states in `ContentView.swift`'s `PlayerScreen` show a `TuningCard` (channel `LogoTile` — moved from file-private to internal so both files can use it — name, current/next programme from cached guide data, a "Tuning…"/"Reconnecting…" spinner), not a bare `ProgressView`.
- **Recordings on tvOS (A4.3, build 21): one player.** `RecordingPlayerScreen` shows `RecordingPlayerView` (`RecordingPlayer.swift`) once ready: `PlayerLayerView` video plus a recording overlay built from the live player's shared parts in `CustomPlayer.swift` (`PlayerActionRow`, `PlayerScrubTrack`, `playerBottomShade`, `BlankButtonStyle`): channel and date, title, scrub bar with elapsed and remaining, Left/Right ±15 s, Play/Pause, a **Skip break** pill while inside a break (Select skips; also first in the action row), an **Auto-skip breaks** toggle in the action row (only when the recording has breaks), Back hides chrome then closes. `RecordingPlayerModel` keeps lifecycle, resume and markers, and gains `timeline()` (`RecordingTimeline`, pure, in `DVRModels.swift`), `skip`, `togglePause` and display criteria (via `PlaybackModel.loadDisplayCriteria`, since a bare layer does not switch HDR/frame rate). The tvOS `AVPlayerViewController` path (contextual action / transport-bar menu) is deleted. **iOS keeps AVKit** (`RecordingNativePlayer`, iOS only) for recordings, because touch scrubbing is AVKit's strength. **C-E `recordingHls`:** a playback answer with `container == "hls"` is played directly (a 200 is returned at once by `APIClient.recordingPlayback`; only 202 polls); `inProgress == true` marks a growing EVENT playlist — no resume (it starts from the start), the scrub bar grows with the seekable end and shows **LIVE** within 20 s of the newest segment while the item's duration is indefinite. `Recording.playLabel(recordingHls:)` decides the details screen's Play button: completed → "Play recording"; status `recording` with the flag → "Watch from start (still recording)"; otherwise none.
- **Timeshift (C-E, build 21, server flag `timeshift`):** `PlaybackModel.timeshift` reads the flag; the date sums are pure functions in `TimeshiftMath` (`Timeshift.swift`, tests `TimeshiftMathTests`): window dates = `currentDate ∓ (currentTime − range end/start)`, Start over allowed when the programme start is inside the window, programme fraction, and the scrub readout (`m:ss` under an hour, `h … min` from an hour). `skip`, `bufferPosition`, `secondsBehindLive` and `goToLive` already use the whole seekable range, so a 3 h window needs no change there. The tvOS info overlay gains **Start over** (`backward.end.fill`) when `startOverProgramme()` is non-nil (the programme at the picture's date began inside the window); it uses `AVPlayerItem.seek(to: Date)` and marks behind-live. When behind live with timeshift, the overlay describes the programme at the picture's date (`currentDate()`), its bar shows the picture's position in that programme (pink, with knob) against live (pale fill), and the picture's clock time sits before now. Without the flag, `seekableDates()`/`playbackDate()` return nil and the player is unchanged.
- **Labs (C-F, build 19):** Settings has a "Labs" section (`LabsToggleRow` in `LibraryView.swift`) of persistent `@AppStorage` switches, all off by default. Keys and wording live only in the `Labs` enum (`Labs.swift`): `pigtv.labs.newGuide` (A2.1 UIKit guide), `pigtv.labs.heaac` (C-C: `PlaybackCapabilities.current()` adds `"heaac": true` only when on; the key is otherwise absent), `pigtv.labs.streamInfo` (A4.2 stream info overlay). Later work reads `Labs.isOn(Labs.newGuide)` etc.; add new switches to `Labs.toggles`.
- **Stream info overlay (A4.2, build 22, Labs → Stream info overlay, tvOS):** with the switch on, the custom player's info overlay adds one line (`StreamInfoLine` in `CustomPlayer.swift`, refreshed every second only while the overlay is up): codec from the video track's format description (H.264/HEVC/…; Dolby Vision from a `dvh1`/`dvhe` entry or a `dvcC`/`dvvC` box, else HDR10/HLG from the transfer function), `presentationSize` @ `nominalFrameRate` (else `currentVideoFrameRate`), indicated bitrate (observed) from the access log's last event, dropped frames summed over access-log events, stalls this session, the resolve route (strategy · video copy/encode) and `ServerInfo.identity`. Gathering is `PlaybackModel.streamStats()`; naming/formatting is pure (`StreamInfo.swift`, tests `StreamInfoTests`). `play-end` events also carry `droppedFrames` and `observedBitrate` (the server's client-event route logs named fields and ignores unknown ones, checked in `routes/playback.js`).
- **Top Shelf (A4.1, build 22, tvOS):** a TV Top Shelf extension target **`PigTVTopShelf`** (`PigTVTopShelf/ContentProvider.swift`, `TVTopShelfContentProvider`, sectioned content; bundle `au.markrogers.PigTV.TopShelf`; tvOS only, embedded in the app's "Embed Foundation Extensions" phase and depended on with `platformFilters = (tvos)` so the iOS build skips it — keep that filter, an iOS build fails without it). One section ("Favourites", else "Channels" = the lineup's first rows) of up to 12 items: logo from its absolute URL (`.hdtv` shape), title `503 · Fox Footy — <programme on now>` (sectioned items have no subtitle, so the programme follows the channel), play/display action `pigtv://play?sourceId=…&id=…&name=…&number=…`. Data: the app writes `topshelf-snapshot.json` into the **App Group `group.au.markrogers.PigTV`** (`Shared/TopShelfSnapshot.swift`, a synchronized folder compiled into both targets; `PigTV/TopShelfExport.swift` builds it from favourites or guide rows with now/next and absolute, credential-free logo URLs) after favourites load, after the guide's first and last page and after the cached guide loads; unchanged content is not rewritten; `topShelfContentDidChange()` is posted; sign-out deletes it. The extension never uses the network. Deep links (`PigTVLink`, also used by Siri): `ContentView.onOpenURL` → `AppModel.open(_:)`: signed in → play (switch if already playing) the guide's channel, else a favourite, else one built from the link's fields; a link arriving before the launch restore finishes is held and played only if that restore succeeds within a minute. Entitlements: `PigTV/PigTV.entitlements`, `PigTVTopShelf/PigTVTopShelf.entitlements` (App Group only); URL scheme `pigtv` in `AppConfiguration.plist`. Tests `TopShelfTests`. **Signing:** automatic signing; Mark's first device build may need Xcode to register the App Group for both bundle IDs (target → Signing & Capabilities; confirm App Groups lists `group.au.markrogers.PigTV` ticked for PigTV and PigTVTopShelf). Until it is registered, the snapshot write fails quietly and the Top Shelf shows the static image.
- **iPhone/iPad (A4.4, build 22):** on iOS with a **compact horizontal size class** (iPhone), `GuideView` shows the **On now list** (`OnNowList.swift`) instead of the one-hour grid: a plain `List` of the filtered rows (logo, number, name, flaky dot, programme on now with a progress bar, next start time and title); tapping a row plays it (with the row order as the zap list), the trailing ⓘ opens `ChannelScheduleView`. Filters and Search stay; Earlier/Later/Jump to… are hidden there (no time axis). Per-row data is the pure `OnNowRow.make` (tests `OnNowRowTests`), computed per visible row. iPad (regular width) keeps the grid. The iOS player's top controls (`iOSControls` in `ContentView.swift`) are one row — close on the left; **Last channel** (`returnToPreviousChannel`, only when one is remembered and differs), channel down/up, Go to number (with `channelNumbers`), Channels sheet on the right — with the number and name in a capsule below, so a long name never squeezes the buttons.
- **Channel numbers (C-A, build 19):** `Channel.number`/`GuideChannel.number` decode the optional server number; `BrowseModel.number(for:)`/`showsChannelNumbers` show it only with the `channelNumbers` flag (so an older server or a stale cached guide shows none), and `asChannel` carries it into player channels. Shown on the guide `ChannelTile` (top-leading), in the tvOS player's side list rows and info overlay, and in iOS `QuickGuidePanel` rows, always via `Text(verbatim:)` so it is never locale-grouped. Channel up/down still follows guide row order (the server orders by number). iOS only: a "Go to number" control in the player (alert with a number field; shown only with the flag) calls `AppModel.goToChannel(numberText:)`, which looks in the zap list, then the guide. tvOS has no number entry.
- **Channel health (C-G, build 19):** `GuideChannel.health` decodes `"ok" | "flaky" | null`; `BrowseModel.isFlaky` is true only for `"flaky"` with the `channelHealth` flag. The guide tile then shows a small amber dot top-trailing, left of the red recording dot when both apply (accessibility label "Unreliable channel", also spoken as the tile button's value).
- **Design rules:** page background `PigPageBackground`; surfaces `Color.guideCell` + `PigSurfaceButtonStyle` (pink accent outline on focus); tvOS type scale in `GuideTypography`; player overlays force dark scheme and provide an opaque fallback for Reduce Transparency. New screens reuse these rather than defining new styles.

## 5. Implementation map and constraints

| Files | Responsibility / things to preserve |
|---|---|
| `Models.swift`, `APIClient.swift` | Info/errors/resolve payloads, status decoding, URL/auth rules. Optional conflict envelope preserves the strict recording type. Status-aware responses support bounded recording polling. Diagnostics strip queries and retain bearer authentication. |
| `AppModel.swift` | Auth and model construction, channel switching. Validated info is retained on the authenticated APIClient through restore/login/pairing and exposed in Settings; logout clears it. Rate-limit cooldown stops immediate repeat auth attempts. |
| `PlaybackModel.swift`, `ContentView.swift`, `CustomPlayer.swift`, `PlayerExtras.swift` (iOS channel sheet) | Player lifecycle, presentation, prompts and controls. `ready` means item installed; actual `.playing` supplies prior-play evidence. Recovery clears the item without permanently ending the model; `stop()` is terminal. Guards coalesce failures and reject stale callbacks/repeated appearances. Late resolve sessions still get released. A1.2: `AppModel.previousChannel` remembers the channel `switchPlayback(to:)` last switched away from; `returnToPreviousChannel()` swaps back to it. Exposed in the tvOS info overlay's action row as "Last channel" (hidden when there is none, or it equals the current channel); no remote shortcut — a long-press-Select alternative was considered and rejected as too fragile against the Button's own Select handling (see the comment in `CustomPlayer.swift`). |
| `RecordingPlayback.swift`, `RecordingPlayer.swift` | Recording preparation/playback and skip/resume (tvOS custom recording player; iOS AVKit). Startup Task is retained/cancelled, checked after suspension points, and awaited before audio teardown. Generation checks reject stale callbacks after retry. 404 wording covers missing recordings and older servers without assuming either. |
| `GuideGrid*.swift` (A2.1) | UIKit guide grid behind Labs → New guide (tvOS). Keep navigation rules in `GuideGridMath` (unit-tested); horizontal offset changes only through `GuideGridCollectionView.setX` / the grid's animator. |
| `BrowseModel.swift`, `GuideView.swift`, `ChannelArtwork.swift` | Guide/cache/artwork; avoid full-day horizontal views and cross-row scroll feedback (previous rendering instability). Gate artwork-index launch and preserve lightweight logo fetching. A1.1: guide paging is cursor-based (`limit=500`+`cursor`) when the server flag `guideCursor` is set, offset-based (`limit=50`+`offset`) otherwise; pages merge into `guide` via a persistent id set, not a per-page rebuild. When `guideVersion` is set, `refreshGuideIfStale` and the cached-guide launch path fetch `GET /api/library/guide/version` and skip the full reload when it matches the version saved with the guide (captured before that load started) and the loaded window still covers the next 12 hours (`GuideNavigation.guideStillCovers`, a pure function). |
| `DVRModels.swift`, `RecordingsView.swift` | Recording states/actions and guide schedule identity; preserve milliseconds versus seconds. |
| `PigTVTests/ContractChecks.swift`, `Tools/test-contracts.sh` | Synthetic contract fixtures and local runner. Targeted simulator lifecycle tests live in `PigTVTests/PlaybackLifecycleTests.swift`; the standalone runner covers API/model fixtures. The scheme sets `PIGTV_SYNTHETIC_TESTS=1` so the test host cannot restore a saved real-server session. |

C2 recovery uses actual playing evidence, allows one automatic attempt per user-initiated playback attempt, and coalesces failure callbacks. A second failure or failed resolve requires Retry; a 409 still requires explicit takeover. Mark confirmed return-to-guide behaviour on 21 September: background cleanup ends playback; foreground return must not automatically resume or reconnect the last channel. Automatic recovery applies only while the player remains active. A stream idle ≥60 seconds can be reclaimed on demand; the idle sweep is five minutes. Confirm AVPlayer paused-fetch behaviour on a real device.

C3: `APIClient.requestURL` rejects `?` in paths; use structured query items. A terminal 500 must stop polling because another request starts a new transcode attempt. Continue using the recording list's duration for resume bounds; playback `durationSec` is wall-clock length.

## 6. Shared contracts and coordination

- Guide rows use `id/sourceId/name/logo/category/tvgId/programmes`, with programme `startTime/endTime` in **milliseconds**. Marker `startMs/endMs` also use milliseconds.
- Favourites writes use bare channel IDs; source-qualified IDs remain useful for local UI identity. Read favourites from `library/favourites`.
- **Resolve errors (C-B, A1.3):** a non-2xx `playback/resolve` whose `error` starts with `The provider refused this channel`, `The provider did not respond` or `This channel is not available` becomes `PigTVError.message` (trimmed to 300 characters; shown by the player's error screen). Any other text, any text containing `://`, and any non-resolve path keep the generic mapping (`APIClient.displayableResolveError`). No flag: a text match.
- Resolve sends `capabilities.segmentedDelivery = true`. “transcode” strategy can mean video/audio copy into HLS, not re-encoding.
- Approved media paths: `/api/proxy/stream`, `/api/transcode/…`, `/api/recordings/…` (`/api/remux` was retired by server 0103 and removed from the client's allow-list and strategy lists in A0.1); tokens on approved media URLs, bearer on session DELETE. Do not broaden URL acceptance to fix playback.
- Recording playback: bearer-authenticated `/api/recordings/{id}/playback`; MP4 response with same-server `media.mp4`, token query and byte-range seeking. Async preparation is additive and opt-in. C-E: with `recordingHls` the answer may be `{url: …/index.m3u8, container: "hls", durationSec, inProgress}` (contract checks cover it).
- Optional flags: `viewerConflict`, `epgLogoFallback`, `clientEvents`, `scheduledWaiting`, `recordingPlaybackPolling`, `playbackTerminalStatus`, `guideCursor`, `guideVersion`, `logoCache` (A1.1; `logoCache` is not yet consumed by the client), `channelNumbers` (C-A), `channelHealth` (C-G), `timeshift` and `recordingHls` (C-E; server env `PIGTV_TUNER=1`). C1/C2 must also handle servers whose behaviour predates the flags, as must guide loading for `guideCursor`/`guideVersion`.
- Adding a client endpoint requires a coordinated addition to server `test/api-404.test.js` → `APPLE_CLIENT_ROUTES`; C7 now calls `POST /api/playback/client-event`; the guard addition is now on local server `main` at `6f8148b`, fast-forwarded from `swift/client-0086-contract-docs` on 21 September without changing runtime code. This server test has not run: Node is not on PATH and server node_modules are absent; no dependencies were downloaded.
- Server 0085/0086 require device regression testing, not client payload changes: copied-video timing/smoothness/lip-sync and finite-source pacing (provider stream `1803789`).
- **Server handoff §5, reviewed to build 0099 (22 September):** 0097 makes favourites follow a reorder-stable channel identity and adds an optional **`stableId`** (client decodes it, R12); 0098 extends it to recordings/history; **0099 ships SR-2** — the small-caps badge is stripped at ingest (client stripper now redundant, R15). All "None to code" — no response shape changes.
- **Open client → server requests in [docs/SERVER-REQUESTS.md](docs/SERVER-REQUESTS.md):** SR-2 (badge) **shipped as 0099**. SR-1 (HDR colour signalling in the HLS copy, client R13) is **still open** — hand it to the server workflow.
- Read server handoff §5 at each integration session. Describe any server request by required user-visible behaviour and record the dependency here. The local server blueprint and Swift handoff now reference this client blueprint instead of its retired handovers. Those were the original client integration changes. The server developer subsequently added the 0094 runtime contract. This review makes no server-repository changes.
