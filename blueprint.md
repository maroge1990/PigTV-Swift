# PigTV Apple client: blueprint

**Last updated:** 25 September 2026 · app **1.0 (28)** · server build 0146 (roadmap contracts C-A…C-G in `../PigTV/docs/ROADMAP-CONTRACTS.md`)

Read this at the start of every session, **together with the joint roadmap in
[`../PigTV/blueprint.md`](../PigTV/blueprint.md) §6**, which is where A-items (Apple) and X-items (both products) are
tracked. This file holds the client's durable facts and rules. It replaced the earlier blueprint on 23 September 2026 after an
independent review; the full U01–U11 and R01–R20 history is frozen in `docs/archive/blueprint-2026-09-23.md`.

## 1. Working rules

- **Push-to-main (Mark, 23 Sept).** Work on `main` in this folder. Claude may `git pull --rebase` and **push to `origin/main`**
  without asking each time. Before every push: the tvOS build and tests pass, plus an iOS build when shared code changed:
  ```bash
  xcodebuild test -project PigTV.xcodeproj -scheme PigTV -destination 'platform=tvOS Simulator,name=Apple TV'
  xcodebuild build -project PigTV.xcodeproj -scheme PigTV -destination 'generic/platform=iOS Simulator'
  ```
  Never force-push. `.gitignore` keeps Xcode and Finder user state out of commits.
- **CI (A0.3).** `.github/workflows/ci.yml` runs on every push to `main` and on pull requests: it selects the runner's
  newest Xcode (failing with a clear message if it is older than the client's minimum), builds for the iOS Simulator, and
  runs the tvOS tests on an Apple TV simulator it finds or creates. It cannot be exercised locally; treat a red run on
  GitHub as equivalent to a local test failure.
- **Bump the build number** (`CURRENT_PROJECT_VERSION`, both app targets in `project.pbxproj`) once per session that changes
  app code, so Settings → Version identifies the installed copy.
- **Organisation:** the lead Claude session delegates implementation to sub-agents and reviews every diff before it's pushed.
  Device-dependent items end with numbered test steps for Mark and become *Verified* only on his report.
- Other internet use still needs Mark's approval: browsing, SDK or dependency downloads, and **contacting the deployed server**.
  Driving the simulator UI (attach, screenshots, input) only when Mark asks in that message; routine checks are `xcodebuild` runs.
- Never send `force: true` automatically: viewer or recording takeover needs an explicit choice. Browsing and focus must never
  acquire a provider stream. Preserve same-origin auth, media URL allow-listing, capability negotiation and release-before-switch.
- Server changes are made in the server repo under its blueprint §2; client-visible server changes appear in
  `../PigTV/docs/SWIFT-CLIENT-HANDOFF.md` §5, so read it at each session start.

## 4. Architecture

- **Screens:** `ContentView` → launch/onboarding/unreachable → `LibraryView` tab container (**Home** (build 28, the tab the app opens on), Guide, Recordings, Settings; tabs are tagged `home`/`guide`/`recordings`/`settings`, `LibraryView.initialTab` lets the fixtures pick one; `ChannelDetails`/`FavouriteControl` in `LibraryView.swift`). Player is presented full screen via `PlayerHost` → `PlayerScreen` → `CustomPlayerView` (tvOS) or `NativePlayer` (iOS).
- **UIKit guide grid (A2.1, build 20; the only tvOS grid since build 27):** on tvOS `GuideView` shows `GuideGridView` (no Labs switch; the SwiftUI grid, its edge targets and `reachedEdge`/`revealIfClipped`/`reapply` were deleted in build 27 and remain only as the iPad layout, compiled for iOS only) (`UIViewControllerRepresentable` → `GuideGridViewController`), keeping its header, filters, summary area and all sheets/covers; the Now button sits in the header next to Earlier/Later (build 22). One `UICollectionView` with a custom `GuideGridLayout`: section = channel row, item 0 = the channel tile (pinned left via the content offset), items 1…n = programmes at `x = (start − model.window) × pointsPerSecond` over the whole loaded 24 h (2 h = the timeline width), or one day-wide "no programme information" placeholder; a now-line decoration; cells clipped at the channel column with the clipped amount passed to the cell (`GuideGridAttributes.leadingClip`) so titles stay visible. The time header is a separate strip view above the rows that follows `contentOffset.x` (so rows never scroll under it). Horizontal position is owned by the grid: `GuideGridCollectionView` locks `bounds.origin.x`, so the focus engine's own scroll-into-view cannot move it sideways; the grid moves by whole half-hour columns with its own 0.2 s ease-in-out display-link animation (none with Reduce Motion). Focus is the collection view's own: `canFocusItemAt` makes finished programmes unfocusable and, in rows other than the focused one, only the Up/Down target (the programme under the time anchor) focusable; `shouldUpdateFocus` plans the column move for Left/Right and redirects Left-onto-the-tile ahead of the live baseline (step back / return to live) via `indexPathForPreferredFocusedView`. Pure maths (positions, clipping, sticky tile, column reveal, vertical target, left step) is in `GuideGridMath.swift`; the row filter is `GuideRowFilter` (shared with the SwiftUI grid). Rows are applied with a plain data source (append → `insertSections`, anything else → `reloadData` + focus restored by identity), not diffable snapshots, because the real guide has ~18 000 channels × ~30 programmes. Files: `GuideGridMath.swift`, `GuideGridLayout.swift`, `GuideGridCells.swift`, `GuideGridView.swift`; tests `GuideGridMathTests`, `GuideGridNavigationUITests` (no launch argument since build 27; `GuideNavigationUITests`, the SwiftUI grid's test, was deleted).
  **Build 21 follow-ups:** (a) when the player or a details cover closes, GuideView bumps `focusRestoreToken` and the grid refocuses its last programme or tile (what is on now in that row if the programme finished meanwhile); (b) Now, Earlier, Later and Jump to move focus with the grid, to the programme under the new anchor in the last focused row (else the first visible row). In both, the grid makes the target its preferred focus (`claimFocus`) and GuideView moves SwiftUI focus into the representable (`.focused($gridHasFocus)`, `claimGridFocus`, retried at 0/0.4/0.8 s while a cover dismisses) — **`UIFocusSystem.requestFocusUpdate` is refused while a SwiftUI control holds focus**, so this must go through SwiftUI. (c) The long-press menu (`contextMenuConfigurationForItemsAt`) already offered the old grid's items; now covered by a UI test (menu items are exposed as `otherElements`). (d) Programme cells rebuild their SwiftUI content only when `GuideGridMath.clipAppearance` (clipped or not, the title's whole-point shift) changes, not on every frame the clipped amount changes; off-screen/unclipped cells get no `apply` during a slide (their attributes are unchanged). Rasterising was not needed. UI tests: Now after moving right; long-press menu and focus back after details. (Superseded in build 22:) on the remote, Up from the grid goes to the header's right-hand buttons (Details, Jump to…), so Now is only reached via the category chips (All → Down).
  **Build 22:** Now moved into the header's button row (before Earlier/Later, new guide only). Up from the grid's top row lands on it: the grid's `shouldUpdateFocus` refuses the engine's move out of the top (no next index path, heading up) and calls `GuideGridActions.leaveUp`, which sets GuideView's `headerNowFocused`. Only Now and Jump to… pull focus into the grid (`GuideGridRequest.focus`); Earlier/Later leave focus on their button so repeated presses work, and claim no grid target. UI tests: `testNowAfterMovingRight` (Up → Now → Select), `testLaterAndEarlierKeepFocusOnTheHeader`.
- **Guide focus model:** `GuideFocus(channel, start)`; `start == nil` is the channel tile, `-1` the no-EPG placeholder (the old tvOS edge targets −2/−3 are gone). On iPad the SwiftUI grid (`timelineGrid`, `GuideTimelineRow`, iOS only) lets the focus engine move between drawn cells. `viewport` (half-hour aligned) drives rendering; `model.window` drives 24-hour data loads.
- **Player layering:** conflict/error/reconnecting states replace the player. **tvOS:** `CustomPlayerView` (`CustomPlayer.swift`) is the only player — `PlayerLayerView` video + one overlay switching between hidden / info / scrub / channels / tracks chrome, driven by in-view remote handlers, no AVKit. **iOS/iPadOS:** `NativePlayer` (plain AVKit) + top controls, with `QuickGuidePanel` as the channel sheet. A1.2: on tvOS, the "Preparing…"/reconnecting states in `ContentView.swift`'s `PlayerScreen` show a `TuningCard` (channel `LogoTile` — moved from file-private to internal so both files can use it — name, current/next programme from cached guide data, a "Tuning…"/"Reconnecting…" spinner), not a bare `ProgressView`.
- **Recordings on tvOS (A4.3, build 21): one player.** `RecordingPlayerScreen` shows `RecordingPlayerView` (`RecordingPlayer.swift`) once ready: `PlayerLayerView` video plus a recording overlay built from the live player's shared parts in `CustomPlayer.swift` (`PlayerActionRow`, `PlayerScrubTrack`, `playerBottomShade`, `BlankButtonStyle`): channel and date, title, scrub bar with elapsed and remaining, Left/Right ±15 s, Play/Pause, a **Skip break** pill while inside a break (Select skips; also first in the action row), an **Auto-skip breaks** toggle in the action row (only when the recording has breaks), Back hides chrome then closes. `RecordingPlayerModel` keeps lifecycle, resume and markers, and gains `timeline()` (`RecordingTimeline`, pure, in `DVRModels.swift`), `skip`, `togglePause` and display criteria (from the asset's `preferredDisplayCriteria`, applied whenever that load finishes and never awaited before playing — build 27 — since a bare layer does not switch HDR/frame rate). The tvOS `AVPlayerViewController` path (contextual action / transport-bar menu) is deleted. **iOS keeps AVKit** (`RecordingNativePlayer`, iOS only) for recordings, because touch scrubbing is AVKit's strength. **C-E `recordingHls`:** a playback answer with `container == "hls"` is played directly (a 200 is returned at once by `APIClient.recordingPlayback`; only 202 polls); `inProgress == true` marks a growing EVENT playlist — no resume (it starts from the start), the scrub bar grows with the seekable end and shows **LIVE** within 20 s of the newest segment while the item's duration is indefinite. `Recording.playLabel(recordingHls:)` decides the details screen's Play button: completed → "Play recording"; status `recording` with the flag → "Watch from start (still recording)"; otherwise none.
- **Timeshift (C-E, build 21, server flag `timeshift`):** `PlaybackModel.timeshift` reads the flag; the date sums are pure functions in `TimeshiftMath` (`Timeshift.swift`, tests `TimeshiftMathTests`): window dates = `currentDate ∓ (currentTime − range end/start)`, Start over allowed when the programme start is inside the window, programme fraction, and the scrub readout (`m:ss` under an hour, `h … min` from an hour). `skip`, `bufferPosition`, `secondsBehindLive` and `goToLive` already use the whole seekable range, so a 3 h window needs no change there. The tvOS info overlay gains **Start over** (`backward.end.fill`) when `startOverProgramme()` is non-nil (the programme at the picture's date began inside the window); it uses `AVPlayerItem.seek(to: Date)` and marks behind-live. When behind live with timeshift, the overlay describes the programme at the picture's date (`currentDate()`), its bar shows the picture's position in that programme (pink, with knob) against live (pale fill), and the picture's clock time sits before now. Without the flag, `seekableDates()`/`playbackDate()` return nil and the player is unchanged.
- **Labs (C-F, build 19):** Settings has a "Labs" section (`LabsToggleRow` in `LibraryView.swift`) of persistent `@AppStorage` switches, all off by default. Keys and wording live only in the `Labs` enum (`Labs.swift`): `pigtv.labs.streamInfo` (A4.2 stream info overlay) is the only one left (`pigtv.labs.newGuide` and `pigtv.labs.heaac` were removed in build 27). Later work reads `Labs.isOn(…)`; add new switches to `Labs.toggles`. **HE-AAC passthrough (C-C) left Labs in build 27:** `PlaybackCapabilities.current()` always sends `"heaac": true` (Mark accepted it); the 'fmt?' → `audioEncode` fallback is the safety net.
- **Stream info overlay (A4.2, build 22, Labs → Stream info overlay, tvOS):** with the switch on, the custom player's info overlay adds one line (`StreamInfoLine` in `CustomPlayer.swift`, refreshed every second only while the overlay is up): codec from the video track's format description (H.264/HEVC/…; Dolby Vision from a `dvh1`/`dvhe` entry or a `dvcC`/`dvvC` box, else HDR10/HLG from the transfer function), `presentationSize` @ `nominalFrameRate` (else `currentVideoFrameRate`), indicated bitrate (observed) from the access log's last event, dropped frames summed over access-log events, stalls this session, the resolve route (strategy · video copy/encode) and `ServerInfo.identity`. Gathering is `PlaybackModel.streamStats()`; naming/formatting is pure (`StreamInfo.swift`, tests `StreamInfoTests`). `play-end` events also carry `droppedFrames` and `observedBitrate` (the server's client-event route logs named fields and ignores unknown ones, checked in `routes/playback.js`).
- **Top Shelf (A4.1, build 22, tvOS):** a TV Top Shelf extension target **`PigTVTopShelf`** (`PigTVTopShelf/ContentProvider.swift`, `TVTopShelfContentProvider`, sectioned content; bundle `au.markrogers.PigTV.TopShelf`; tvOS only, embedded in the app's "Embed Foundation Extensions" phase and depended on with `platformFilters = (tvos)` so the iOS build skips it — keep that filter, an iOS build fails without it). One section ("Favourites", else "Channels" = the lineup's first rows) of up to 12 items: logo from its absolute URL (`.hdtv` shape), title `503 · Fox Footy — <programme on now>` (sectioned items have no subtitle, so the programme follows the channel), play/display action `pigtv://play?sourceId=…&id=…&name=…&number=…`. Data: the app writes `topshelf-snapshot.json` into the **App Group `group.au.markrogers.PigTV`** (`Shared/TopShelfSnapshot.swift`, a synchronized folder compiled into both targets; `PigTV/TopShelfExport.swift` builds it from favourites or guide rows with now/next and absolute, credential-free logo URLs) after favourites load, after the guide's first and last page and after the cached guide loads; unchanged content is not rewritten; `topShelfContentDidChange()` is posted; sign-out deletes it. The extension never uses the network. Deep links (`PigTVLink`, also used by Siri): `ContentView.onOpenURL` → `AppModel.open(_:)`: signed in → play (switch if already playing) the guide's channel, else a favourite, else one built from the link's fields; a link arriving before the launch restore finishes is held and played only if that restore succeeds within a minute. Entitlements: `PigTV/PigTV.entitlements`, `PigTVTopShelf/PigTVTopShelf.entitlements` (App Group only); URL scheme `pigtv` in `AppConfiguration.plist`. Tests `TopShelfTests`. **Signing:** automatic signing; Mark's first device build may need Xcode to register the App Group for both bundle IDs (target → Signing & Capabilities; confirm App Groups lists `group.au.markrogers.PigTV` ticked for PigTV and PigTVTopShelf). Until it is registered, the snapshot write fails and the Top Shelf shows the static image.

Also: a failed snapshot write is no longer remembered as written (the next export retries). **Diagnostics:** `TopShelfLog` (os `Logger`, subsystem `au.markrogers.PigTV.TopShelf`, category = process bundle id) logs the app's export/write (`write: N favourites channels to …`, or `no App Group container`), `topShelfContentDidChange posted`, and the extension's `loadTopShelfContent called`, `read: … bytes, N channels` / `no snapshot` / `no App Group container`, each item's logo URL (debug) and `returning N items`. - **Siri / App Intents (A4.5, build 22, iOS and tvOS):** `PlayChannelIntent` ("Play channel", `openAppWhenRun`) with a `ChannelEntity` parameter; `ChannelQuery` (an `EntityStringQuery`) searches `channel-directory.json` in the App Group (every guide channel's id/sourceId/name/number, written by `BrowseModel.exportChannelDirectory()` when the whole guide or the cached guide loads; deleted on sign-out), falling back to the Top Shelf snapshot; suggestions are the Top Shelf's channels. - **Swift 6 (A4.5, build 22; reverted in build 23; back for good in build 28):** the app and Top Shelf targets build in the Swift 6 language mode. **Build 28 callback audit:** every AVFoundation/KVO/notification callback is explicitly `@Sendable` (nonisolated) — `PlaybackModel`'s item-status and `timeControlStatus` KVO handlers, its failed-to-play-to-end and stalled notifications, the Start over seek completion, `RecordingPlayerModel`'s status KVO — and hops to the main actor with `Task { @MainActor in … }`; only where the queue is guaranteed main (`addPeriodicTimeObserver(queue: .main)` in the recording player, `TabBarStyle`'s `queue: .main` focus notification) is `MainActor.assumeIsolated` used. The URLSession delegates (`NoRedirects`, `ArtworkRedirects`) are `nonisolated` (URLSession calls them on its own queue; with the default main-actor isolation a redirect would have trapped). The App Intents types (`ChannelEntity`, `ChannelQuery`, `PigTVShortcuts`, and `PlayChannelIntent`'s static metadata) are nonisolated; `perform()` stays `@MainActor`. UIKit delegates, `DispatchQueue.main.async` and the display link run on main. The real-playback harness runs these KVO/notification/time-observer paths for real (including the recording player's periodic observer and a real -11868 status failure) and passes under Swift 6. Build 22's notes: The switch needed nine small changes, none behavioural: pure value types/helpers marked `nonisolated` (`ServerAddress`, `Labs`, `Category`, `TimeshiftMath`, `StreamStats`, `StreamInfoFormat`); `GuideGridAttributes.isEqual` `nonisolated` with `leadingClip` `nonisolated(unsafe)` (NSObject's `isEqual` is nonisolated; UIKit uses attributes on the main thread); (`PlaybackModel.loadDisplayCriteria` was removed in build 27, see below). New code should keep pure helpers `nonisolated` so the Swift 5 test targets can call them.

- **Display mode without waiting (build 27).** Device log: first picture − resolve ≈ 3.0 s on every start, because `PlaybackModel.start` awaited `loadDisplayCriteria(item.asset)` (bounded by 3 s) before `replaceCurrentItem`, and on the device the live master playlist's criteria never arrived in time. Now `DisplayMode` (`DisplayMode.swift`, pure, tests `DisplayModeTests`) builds the criteria from the resolve decision: `PlaybackDecision.info` (decoded tolerantly as `ResolveStreamInfo`: `fps`, `videoRange`, `video`, `width`, `height`) → refresh rate (the server's `parseFrameRate` rules, 1…240 fps) and range (PQ/HLG only when the video is not encoded, else SDR) → a `CMVideoFormatDescription` whose extensions carry the transfer function (SMPTE ST 2084 / ITU-R 2100 HLG / ITU-R 709), primaries and matrix (BT.2020 for HDR) → `AVDisplayCriteria(refreshRate:formatDescription:)` (AVFoundation, tvOS 17+, not an AVKit category). `installItem` sets it and plays immediately. With no usable `fps` (older server, direct route) the asset's criteria are loaded in the background and applied if the item is still current. Recordings do the same (background load, never awaited). **Rule: nothing may await before `replaceCurrentItem`/`play()` except the resolve and the audio session.**
- **Device-error fallbacks (build 27).** `PlaybackFallback.for(_:)` classifies the failed item's error chain (`PlayerErrorCode`s from the item's error and its underlying errors, or the failed-to-play-to-end notification's error). **-11868** in `AVFoundationErrorDomain` (no compatible alternates for the display: the HDR master playlist on a non-HDR TV) → play the same session's `stream.m3u8` (same directory and token, `PlaybackModel.streamPlaylistURL`) with no display criteria and a fresh play-start event; no new resolve. **1718449215 = `'fmt?'`** (copied audio the device cannot decode) → release and resolve again with `ResolveBody.audioEncode = true` (absent otherwise; the server re-encodes only the audio) and remember the channel's `identityKey` in `AudioEncodeMemory` (UserDefaults `pigtv.audioEncode.channels`), so later plays request it from the first resolve. Either fallback uses up the one C2 recovery (`recoveryUsed`), happens at most once per user-initiated attempt, never forces, and a repeat of the error goes to the normal error/Retry path. Tests in `PlaybackLifecycleTests` (synthetic failures; the media host is TEST-NET-1 so the real item never fails first).
- **Tab bar (build 27, tvOS, `TabBarStyle.swift`).** Mark: the selected tab, once focus moved into the page, was pink text on the system's light grey pill. tvOS draws the focused pill and the selected-unfocused pill from the same `UITabBarAppearance.selectionIndicatorTintColor` (checked by screenshot: setting it solid pink hid the pink selected text; faint made the focused pill faint), and moving focus along the bar selects the tab, so the two never coexist. `TabBarStyle.apply()` (from `PigTVApp.init`) sets `UITabBar.appearance()` and watches `UIFocusSystem.didUpdateNotification`: focus in the bar → solid pink pill, white text and icon (`item.focused`); focus in the page → selected tab pink text over a faint pink pill (22 % dark / 12 % light), others system colours; in light mode the bar is near-white (`backgroundColor` 85 % white) instead of mid grey. The guide fixture honours `PIGTV_UI_TEST_APPEARANCE=light|dark` (`simctl ui appearance` is unsupported on the tvOS runtime), which is how both modes were checked.

## 6. Shared contracts and coordination

- Guide rows use `id/sourceId/name/logo/category/tvgId/programmes`, with programme `startTime/endTime` in **milliseconds**. Marker `startMs/endMs` also use milliseconds.
- Favourites writes use bare channel IDs; source-qualified IDs remain useful for local UI identity. Read favourites from `library/favourites`.
- **Resolve errors (C-B, A1.3):** a non-2xx `playback/resolve` whose `error` starts with `The provider refused this channel`, `The provider did not respond` or `This channel is not available` becomes `PigTVError.message` (trimmed to 300 characters; shown by the player's error screen). Any other text, any text containing `://`, and any non-resolve path keep the generic mapping (`APIClient.displayableResolveError`). No flag: a text match.
- Resolve sends `capabilities.segmentedDelivery = true`. “transcode” strategy can mean video/audio copy into HLS, not re-encoding.
- Approved media paths: `/api/proxy/stream`, `/api/transcode/…`, `/api/recordings/…` (`/api/remux` was retired by server 0103 and removed from the client's allow-list and strategy lists in A0.1); tokens on approved media URLs, bearer on session DELETE. Do not broaden URL acceptance to fix playback.
- Recording playback: bearer-authenticated `/api/recordings/{id}/playback`; MP4 response with same-server `media.mp4`, token query and byte-range seeking. Async preparation is additive and opt-in. C-E: with `recordingHls` the answer may be `{url: …/index.m3u8, container: "hls", durationSec, inProgress}` (contract checks cover it).
- Optional flags: `viewerConflict`, `epgLogoFallback`, `clientEvents`, `scheduledWaiting`, `recordingPlaybackPolling`, `playbackTerminalStatus`, `guideCursor`, `guideVersion`, `logoCache` (A1.1; `logoCache` is not yet consumed by the client), `channelNumbers` (C-A), `channelHealth` (C-G), `timeshift` and `recordingHls` (C-E; server env `PIGTV_TUNER=1`). C1/C2 must also handle servers whose behaviour predates the flags, as must guide loading for `guideCursor`/`guideVersion`.
- Adding a client endpoint requires a coordinated addition to server `test/api-404.test.js` → `APPLE_CLIENT_ROUTES`; C7 now calls `POST /api/playback/client-event`; the guard addition is now on local server `main` at `6f8148b`, fast-forwarded from `swift/client-0086-contract-docs` on 21 September without changing runtime code. This server test has not run: Node is not on PATH and server node_modules are absent; no dependencies were downloaded.
- Server 0085/0086 require device regression testing, not client payload changes: copied-video timing/smoothness/lip-sync and finite-source pacing (provider stream `1803789`).

- AirPlay, PiP and background playback remain outside current scope; preserve existing restrictions until session ownership supports them.
- Avoid speculative VOD/series work. Guide/player changes are now explicitly scoped in §4a; the implemented channel browser still needs device UX acceptance.

**Crash on channel start (builds 21–23), fixed in builds 24–25.** The real cause, from the device console (Mark, test 1.9):
`-[AVPlayerItem setExternalMetadata:]: unrecognized selector`. `externalMetadata` is an AVKit category on AVPlayerItem.
Once build 21 retired the last AVKit player on tvOS, AVKit was no longer loaded, and setting it crashed the moment a
channel started. `PlaybackModel.setExternalMetadata` now sets it only when the selector exists, and a test reproduces the
crash on the old code. Build 25 also **links AVKit explicitly for tvOS** (`OTHER_LDFLAGS[sdk=appletv*] = -framework AVKit`): `UIWindow.avDisplayManager` (HDR/50 Hz switching) is an AVKit category too and would have crashed next. `testAVKitCategoriesAreAvailableOnTV` guards both. **Lesson:** never call AVKit-only API on tvOS without checking it exists; the simulator tests
missed this because no test started a real player item.

Build 23 also moved the app target back to Swift 5 on a wrong diagnosis (the KVO-isolation theory). **Build 28 returned to
Swift 6** (Mark approved) with every KVO/AVFoundation callback explicitly `@Sendable`/nonisolated (see §4 Swift 6) and the
real-playback harness exercising them; verify with real playback on the TV.
